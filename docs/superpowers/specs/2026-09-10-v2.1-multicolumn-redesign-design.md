# v2.1 Multicolumn Whitepaper Redesign — Design

Date: 2026-09-10
Status: Approved (pending written-spec review)
Branch: `v2.1`

## Context

The v2 site rendered content as cards on a d3 force-directed graph (branch `v2`).
This redesign replaces that UI entirely with a static, whitepaper-style document:
cosmic-latte background, black text, a left-aligned masthead, and sections that flow
across responsive CSS columns. The typography stack (fonts, Knuth-Plass
justification, hyphenation, protrusion) and the `content.yml`-driven content model
are kept.

## Decisions

| Decision | Choice |
|---|---|
| Layout | CSS multi-column flow (`column-count` + custom separator lines) |
| Theme | White background, black text/rules only; no dark mode, no toggle |
| Columns | 1 (<640px), 2 (640–1919px, typical desktops), 3 (≥1920px); three is the maximum |
| Column fill | Browser default (`balance`); page scrolls only if 4 columns cannot fit |
| Content key | `cards` → `sections`; new `meta.subtitle`, `meta.links` |
| Graph/router/theme | Deleted (modules, tests, vendor d3) |
| Typography | Unchanged libs; fonts self-hosted as WOFF2 with preload; justification re-runs on resize/column change |

## Layout & Flow

- Page container: centered, `max-width: 1600px`, padding `clamp(1.5rem, 4vw, 4rem)`.
- Masthead above the flow: title, subtitle, links row (all left-aligned).
- Flow region `.paper`:
  - `column-count: 1; column-gap: 2.5rem;`
  - Media queries raise `column-count` to 2 at 640px and 3 (maximum) at 1920px.
  - Separators are 1px black lines drawn as absolutely positioned
    `.paper::before`/`::after` elements at the gap centers (one line for 2 columns
    at 50%, two for 3 columns at `calc(33.3333% - 0.4167rem)` and
    `calc(66.6667% + 0.4167rem)`), never at the outer edges. They overhang the
    content by `0.8em` (half a 1.6 line-height) at the top and bottom.
- Sections are ordinary flow content in `content.yml` order:
  `<section><h2>Projects</h2><p>…</p></section>`.
- Keep headings with their content: `h2 { break-after: avoid; }`; keep link rows and
  headings unbroken: `break-inside: avoid;`.
- Vertical rhythm: body `line-height: 1.6`; paragraphs have no first-line indent and
  a half-line gap (`p + p { margin-top: 0.8em }`). Headings sit closer to their own
  section than to what precedes them: `section + section { margin-top: 2.25rem }`
  above, `h2 { margin-bottom: 0.4em }` below (at 1200px: ~36px above vs ~14px below).
- With `column-fill: balance`, short content produces shorter balanced columns; when
  the content cannot fit at 4 columns, the document height exceeds the viewport and
  the page scrolls. This is the accepted fallback.

## Masthead

- `h1` — `meta.title` ("Daniil Sobol`): GOST Type A, `clamp(2.2rem, 5vw, 3.6rem)`,
  black, tracking `0.01em` (optical tracking: tighter at display sizes).
  `document.title` is set to `meta.title`.
- `p.subtitle` — `meta.subtitle` ("distributed systems engineer"): Latin Modern Roman,
  `1.05–1.25rem`, black.
- `nav.links-row` — `meta.links` (GitHub, Email, Telegram), separated by a 1px black
  vertical rule (~0.9em tall, 0.75em side margins) via `a + a::before`.
- Header bottom margin ~2.5rem.
- Links: `#3a4666`, underlined (1px, offset 0.15em); hover thickens the underline
  to 2px. Same treatment for section link rows and body links.

## Content Model — `content.yml`

```yaml
meta:
  title: Daniil Sobol
  subtitle: distributed systems engineer
  links:
    - label: GitHub
      url: https://github.com/mynameisdaniil
    - label: Email
      url: mailto:sobol.daniil@gmail.com
    - label: Telegram
      url: https://t.me/mynameisdaniil
sections:
  - id: projects
    title: Projects
    body: |
      Erlang client for Ethereum Portal Network: [ePortalD](https://eportald.org/)

      Zig (C-compatible) client for Ethereum Portal Network: [libportal](https://libportal.net/)
  - id: writing
    title: Writing
    body: |
      [My take on FP introductory article via Haskell](https://habr.com/ru/post/319440/)

      [YAFF — asynchronous stream-oriented programming before it became mainstream](https://habr.com/ru/post/251307/)
  - id: facts
    title: Facts
    body: |
      …21 facts, one per paragraph…
  - id: contact
    title: Contact
    body: |
      The best way to contact me is email; I'm also around on these:
    links:
      - label: Telegram
        url: https://t.me/mynameisdaniil
      …nine more…
```

Rules:

- `meta.title` and `meta.subtitle` are required non-empty strings.
- `meta.links` is an optional list; each item requires `label` and `url`
  (external or `mailto:`). Internal/card links are no longer supported.
- `sections` is a required non-empty list. Each section: `id` (slug `[a-z0-9-]+`,
  unique), `title` (required), optional markdown `body`, optional `links` list
  (same shape as `meta.links`), optional `lang` for hyphenation.
- `buildModel(raw) → { meta: { title, subtitle, links }, sections: [...], errors }`.
  No edges, no `default_card`, no internal link resolution.
- The facts' 21 paragraphs and current copy carry over unchanged from `content.yml`.

## Typography Pipeline

- Section headings (`h2`, GOST Type A) are `clamp(1.7rem, 1.2rem + 2vw, 2.2rem)`
  (~1.5–2× body), rendered in small caps via `font-variant-caps: small-caps`,
  and tracked open at `0.06em` (small caps need more spacing than lowercase).
  GOST Type A has no `smcp` feature, so this is browser-synthesized small caps;
  if the synthesis quality is unsatisfactory, swap the family to the available
  Latin Modern Roman Caps face instead.
- Micro-typography: `orphans: 2`/`widows: 2` keep paragraph fragments readable;
  kerning and standard ligatures stay at browser defaults. Do NOT set
  `font-kerning` or `font-variant-*` on measured text: Chrome then returns an empty
  computed `font` shorthand, and tex-linebreak's canvas measurement silently falls
  back to 10px sans-serif, producing wrong line breaks and overflow.
  `js/typography.js` warns when the computed font is empty.
- Protrusion tables cover straight and curly quotes, guillemets, parentheses,
  brackets, hyphens, en/em dashes, and ellipses; each line's first and last
  non-space character is found across inline elements.
- A smart-punctuation pass rewrites rendered text nodes (`'` → `’`, paired `"` →
  `“ ”`, `...` → `…`, `--` → `–`, `---` → `—`); attribute values and
  `code`/`pre` content are untouched.
- Measure calibration: body is 18px except in the 2-column range
  (1024–1919px), where it scales `clamp(18px, 0.6rem + 0.75vw, 21px)` so lines
  stay ~49–68 characters; 1-column and 3-column layouts keep 18px.
- Fonts ship as WOFF2 (built by `npm run build:fonts` from the TypoPRO TTFs and
  the Metrolog release TTF via `wawoff2`); the masthead and body faces are
  preloaded in `index.html` with `as="font" type="font/woff2" crossorigin`.
- Unchanged: `document.fonts.ready` → for each flow paragraph,
  `typography.justifyContent(paragraphs, hyphenateFor(lang))` → protrusion pass;
  debounced re-run on resize (150ms) and after a column-count breakpoint change.
- `js/typography.js` generalizes its selector from `.card-body p` to all `p`
  within the element it is given.
- Section link rows are not justified (they are inline-flex rows).
- Risk: measuring justified text inside a fragmented multicol container. Browser
  verification covers it; if measurement is wrong, re-measure/justify per paragraph
  against the explicit column width without changing the public interface.
- `lang` per section (default `en-us`) drives the hyphenator.

## Error Handling

`content.yml` failure (fetch, parse, or validation) renders a minimal error state in
the document body: a paragraph "Could not load content." plus a `<ul>` of validation
details, and logs the full error to `console.error`. No masthead is rendered when
`meta` cannot be loaded. The page never stays blank or throws uncaught.

## Accessibility

- Masthead links are real `<a>` elements in a labeled `<nav>`.
- Sections use `<h2>` under the `<h1>`; document outline is linear.
- Column rules are decorative (CSS background, not content).
- Contrast is maximal (black on cosmic latte `#fff8e7`); links are `#3a4666` on
  cosmic latte (~9.3:1).
- Visible focus is a 2px link-colored outline; text selection is ink on the link
  color.
- `prefers-reduced-motion` is moot (no animation remains).

## Verification

1. `npm test` — updated model suite plus content and protrusion suites pass.
2. Headless Chromium at widths 375 / 800 / 1200 / 1600:
   - computed `column-count` is 1 / 2 / 3 (2 on regular desktops, 3 max) and separator lines sit at gap centers;
   - sections appear in order; headings are not separated from their first paragraph;
   - at 1600×1000 the page scrolls only because the content exceeds the viewport;
   - justification/hyphenation/protrusion active inside columns;
   - header/section link separators render; no console errors; no external requests.
3. Human visual pass.

## Non-Goals

- No dark mode, no graph, no hash routing/deep links, no animations.
- No print stylesheet in this pass (candidate follow-up).
- No content changes beyond the schema restructure and masthead extraction.

## Definition of Done

- White page with black text; masthead title/subtitle/links left-aligned.
- Sections flow across 1/2/3 columns by viewport (2 at regular desktop widths, 3 max); thin black rules between columns.
- Full typography pipeline (fonts, Knuth-Plass, hyphenation, protrusion) works in the
  columns and re-runs on resize.
- Graph/card/router/theme code and d3 are gone; tests updated; no console errors.
