# v2: Force-Directed Card Graph — Design

Date: 2026-09-10
Status: Approved (pending written-spec review)
Branch: `v2`

## Context

The current site is an Elm application (`src/Main.elm`) that renders `contents.yaml`
as randomized text blocks, plus a large generated `index.html`, slide decks, icons,
and other assets (410 tracked files). It is being replaced entirely.

The v2 site is a single-page, static, GitHub Pages site whose primary interface is a
force-directed graph. Graph vertices are content cards; edges are links between cards.
One card is focused at a time; the rest recede into a blurred, scaled-down background.
Focus transitions are driven by a live `d3-force` simulation.

## Goals

- Scrap the old site except `CNAME`; keep a `content.yml`-driven content model.
- D3 force-directed graph of cards; clicking navigation links animates a card into
  focus while the rest recede.
- LaTeX-grade typography: GOST Type B titles, Latin Modern Roman body, Tex (Knuth-Plass)
  line breaking, Hypher hyphenation, microtype-style protrusion.
- Warm/cool gray visual language, light and dark themes following system preference
  with a top-right toggle.
- Tailwind CSS and all JS vendored/self-hosted; GitHub Pages deploy requires no build.

## Non-Goals

- No server-side rendering, no CMS, no backend.
- No JavaScript build step at deploy time (dev-time generators only; outputs committed).
- No math rendering (KaTeX) in v1.
- No mobile-specific alternate layout; the graph experience is responsive.
- No accent/chromatic color; the palette is grayscale only.

## Decisions

| Decision | Choice |
|---|---|
| Stack | Vanilla JS ES modules (no Elm) |
| Graph | Live `d3-force` simulation (`Approach A`) |
| Deploy | Static GitHub Pages; no CI/build |
| Tailwind | CLI-built CSS committed (`assets/tailwind.css`) |
| Vendor libs | Self-hosted in `assets/vendor/` |
| Fonts | Self-hosted GOST Type B + Latin Modern Roman |
| Body markdown | Client-side `marked`, trusted content |
| Line breaking | `tex-linebreak` + `hypher` patterns (`en-us`, `ru`) |
| Protrusion | Own post-justification pass (microtype-style hanging punctuation) |
| Routing | `location.hash` deep links + back/forward |
| Theme | System default, toggle persisted in `localStorage` |

`Hyphenopoly` and `microtypejs` were evaluated and rejected:

- `Hyphenopoly` is an async CSS-`hyphens` polyfill; `tex-linebreak` already hyphenates
  synchronously via `hypher`. Using both causes two systems to mutate the same text nodes.
- `microtypejs` clears paragraphs with `innerHTML = ""`, destroying inline markup
  (links, emphasis), uses a greedy line breaker, and is English-only. Its one additive
  feature, character protrusion, is reimplemented in ~50 lines in our pipeline.

## Data Model — `content.yml`

```yaml
meta:
  title: Daniil Sobol
  default_card: about
cards:
  - id: about
    title: Daniil Sobol
    body: |
      Software engineer. (markdown, rendered client-side)
    links:
      - label: GitHub
        url: https://github.com/mynameisdaniil
      - label: Email
        url: mailto:sobol.daniil@gmail.com
```

Rules:

- `meta.default_card` is required and must reference an existing card `id`.
- Card `id`s must be unique and URL-safe (`[a-z0-9-]+`).
- `links[]` items contain exactly one of:
  - `url` — external link, rendered `target="_blank" rel="noopener noreferrer"`;
  - `card` — internal link to another card `id`; this also creates a graph edge.
- Graph edges are derived from internal links; there is no separate edge list.
- Validation errors (duplicate ids, missing/unknown `default_card`, unknown `card`
  target, malformed cards) render a single centered error card and log details.

## Architecture

### Module responsibilities

- `main.js` — orchestration only: load YAML, validate, build model, wire router,
  instantiate graph, theme, and typography. Owns the top-level error state.
- `content.js` — pure-ish: `fetch content.yml` → `js-yaml` parse → validate →
  model `{meta, cards: Map, edges: []}`; `renderMarkdown(body) → HTML string`.
- `graph.js` — owns the simulation and DOM placement:
  `initGraph(model, { onFocusCard })`, `focusCard(id)`, `onResize()`.
  Sets `transform` on card elements and updates edge endpoints on tick.
- `card.js` — builds card DOM (`<article>`), focused/background class toggles,
  lazy body rendering (body HTML is generated on first focus), link handling.
- `typography.js` — `document.fonts.ready` → `justifyContent` on focused card
  paragraphs → protrusion pass; debounced re-run on resize/focus; exposes
  `clearJustification(el)`.
- `router.js` — reads/validates `location.hash`; `hashchange` listener; Esc →
  default card; updates `document.title`; reports focus changes to `graph.js`.
- `theme.js` — applies/removes `.dark`, persists `light`/`dark` override to
  `localStorage`, reacts to system changes when no override is set.

### Data flow

```
fetch content.yml
  → parse/validate → model {cards, edges, defaultCard}
  → render all card shells (titles only)
  → d3-force simulation over nodes/edges
  → router reads hash (or default) → focusCard(id)
      → card.js expands focused card, lazy-renders markdown body
      → graph re-heats; layout animates
      → typography.js justifies + protrudes focused card body
      → router updates hash/title/aria
```

## Graph & Focus Mechanics

- One `<svg>` layer for edges beneath absolutely positioned HTML `<article>` cards.
- Simulation forces:
  - `forceManyBody` (repulsion),
  - `forceLink` (distance differs for edges adjacent to the focused node),
  - `forceCollide` (radius = card half-diagonal when focused; small when background),
  - soft boundary force keeping nodes within the viewport,
  - weak centering pull on the focused node toward the viewport center.
- Focus change mutates node data (focused flag + measured size) and re-heats the
  simulation (`alpha 0.6`); nodes settle and cool naturally.
- Background cards: `scale(0.6)`, `blur(5px)`, `opacity ~0.45`, title-only, clickable.
- Focused card: full opacity, no blur, internal scroll, links visible.
- Positions are applied exclusively via `transform`; no layout-triggering writes.
- Edges touching the focused node render stronger; others fade.
- Background card bodies are never rendered until first focused.
- Resize (`ResizeObserver`, debounced) updates center/boundary forces and card
  measurements without restarting the simulation.

## Typography Pipeline

Frame: GOST Type B (titles), Latin Modern Roman (body), self-hosted with `@font-face`.

```
render markdown → document.fonts.ready
  → tex-linebreak justifyContent(focusedCard paragraphs, hypherHyphenate)
  → protrusion pass
  → fade focused card in
```

- `tex-linebreak` (Knuth-Plass) preserves inline markup and supports
  `unjustifyContent` for idempotent re-runs.
- `hypher` with `hyphenation.en-us` and `hyphenation.ru`; language is chosen per card:
  `card.lang` if present, otherwise the page default (`<html lang="en">` → `en-us`).
  Unknown languages fall back to `en-us`.
- Protrusion pass: for each line (delimited by `tex-linebreak`-inserted `<br>`),
  wrap the first and last edge punctuation in spans with negative em margins.
  Left set: `" ' « » ( [ -`. Right set: `, . ! ? : ; " ' » ) ] -`.
  Defaults: `.` 0.15em, `-` 0.2em, `,`/`!` 0.1em, others 0.05–0.1em.
  Native `hanging-punctuation` is not used (avoid double application; inconsistent
  browser support).
- Justification runs on the focused card only. Re-run on focus change and debounced
  window resize. Theme change does not invalidate metrics.
- Failure mode: if justification throws, the card remains readable with normal
  wrapping (error logged, no user-facing break).

## Visual System

CSS custom properties on `:root` and `.dark`:

| Token | Light | Dark |
|---|---|---|
| `--bg-center` | warm `#f7f5f2` | warm `#1c1d20` |
| `--bg-edge` | cool `#e3e6eb` | cool `#101216` |
| `--card-bg` | `rgb(90 98 110 / 0.07)` | `rgb(200 206 216 / 0.05)` |
| `--card-border` | `#1d1c1b` (1px) | `#d9d5ce` 55% (1px) |
| `--text` | warm `#3b3835` | warm `#b8b4ad` |
| `--title` | cool `#22252b` | cool `#e6e8ec` |
| `--edge-line` | cool `#8a92a0` 25% | warm `#9a958d` 20% |

- Background: `radial-gradient(circle at 50% 45%, var(--bg-center), var(--bg-edge))`.
- Cards: 1px border, 4px radius, translucent fill, `backdrop-filter: blur(10px)`;
  focused card gets stronger fill and a faint shadow. No color accent, no glow.
- Links: inherit text color; underline with offset; hover thickens underline via
  `text-decoration-thickness`.
- Title: GOST Type B, slight tracking, `clamp(1.6rem, 4vw, 2.6rem)`.
- Body: Latin Modern Roman, 18px, `line-height: 1.55`, `max-width: 65ch`,
  `text-rendering: optimizeLegibility`, common ligatures.
- LaTeX paragraph style: `p + p { text-indent: 1.5em }`, no vertical margins between
  paragraphs.
- Theme: inline `<head>` script applies `.dark` before first paint (no flash);
  toggle top-right (inline SVG sun/moon), `aria-pressed`, persisted in `localStorage`
  under `theme`; otherwise follows `prefers-color-scheme`. `color-scheme` set per theme.

## Routing, States, Accessibility

### Routing

- Focus state ↔ `location.hash` (`#about`).
- On load: hash if valid, else `meta.default_card`.
- `hashchange` handles back/forward. Unknown id → default card.
- Esc focuses the default card.
- `document.title` becomes `<meta.title> — <card title>` when not default.

### Loading & errors

- The stage (`#stage`) starts `visibility: hidden`; after the focused card is
  justified it fades in. No separate loader element in v1.
- Fetch/parse/validation failure → centered error card with a short message;
  full details in `console.error`.
- Markdown is trusted (author-owned content); no sanitizer in v1.

### Accessibility

- Cards are `<article>` and keyboard-focusable; Enter/Space focuses a background card.
- Real `<a>` elements for links; `aria-current="page"` on the active card's links.
- Polite live region announces "Showing <card title>".
- Contrast ≥ 4.5:1 in both themes; blur is decorative.
- `prefers-reduced-motion: reduce` → no blur/scale animation and instant reflow.
- Focus moves to the focused card's heading after navigation.

### Responsive

- Focused card: `width: min(42rem, 92vw)`, `max-height: min(80vh, 720px)`,
  `overflow: auto` for the body.
- Background cards shrink on narrow viewports; simulation boundary and charge
  distances adapt to viewport size.
- Font sizes via `clamp()`; touch targets ≥ 44px.

## Verification

Local server: `python3 -m http.server`, open `http://localhost:8000`.

Manual checklist:

1. Single card loads from `content.yml`: title in GOST Type B, body in Latin Modern.
2. Text is justified with hyphenation and protrusion; no orphaned punctuation overflow.
3. Light/dark: system default honored on first visit; toggle flips instantly and
   persists across reload; no flash of wrong theme.
4. Hash: `#about` loads directly; back/forward traverse focus; unknown hash → default.
5. Resize: layout re-justifies (debounced); simulation boundary adapts.
6. Keyboard: Tab reaches cards/links, Enter focuses, Esc returns to default.
7. Reduced motion: focus changes are instant, no blur animation.
8. Error path: temporarily rename `content.yml` → error card + console detail.
9. No CDN/network requests: all assets served locally; no console errors.
10. Add a temporary second card to content.yml and confirm focus animation, edges,
    and background blur/scale work, then remove it.
